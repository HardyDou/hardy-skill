# skill-test 使用指南

## 快速开始

### 安装

```bash
npx skills add HardyDou/hardy-skill/skill-test -g -y
```

### 基本用法

**搜索并测试相关 skills**
```
测试 写文章 相关skill
```
流程：搜索 → 列表选择 → 自动测试 → 生成报告

**直接测试指定 skill**
```
测试 humanizer-zh
```

**查看结果**
```
进度                              # 显示所有测试
报告 humanizer-zh                  # 查看单个报告
对比 humanizer-zh wechat-converter # 对比两个 skills
```

## 输出结构

```
[业务类型]/              ← 如 writing
├── [skill名]/
│   ├── input.md        ← 测试输入
│   ├── output.*        ← skill 产出
│   ├── process.txt     ← 完整对话（含交互问答）
│   └── REPORT.md       ← 评测报告（5维度评分）
└── SUMMARY.md          ← 汇总对比
```

### 评分维度（1-5 分，总分 25）

- **输出质量** - 准确性、完整性、精致度
- **响应速度** - 执行时间（含专家咨询）
- **指令遵循** - 遵循文档行为程度
- **实用性** - 真实世界价值
- **成本效率** - Token 使用量与价值比

## 核心特性

### 自动交互处理

当被测 skill 提问时，自动召集领域专家回答，无需人工干预：
- 内容策略专家（写作类）
- 产品管理专家（产品类）
- UX/UI 设计专家（设计类）
- 软件架构专家（架构类）
- 通用领域专家（其他）

所有交互记录在 `process.txt` 中。

### 成本追踪

自动运行 `/usage` `/cost` `/export` 命令，记录每个 skill 的 token 使用量和成本。

### 会话隔离

每个 skill 测试后自动 `/clear`，防止成本累积和指标重叠。

## 典型场景

**场景 1：选择最佳 skill**
```
测试 去AI痕迹 相关skill
```
自动搜索、测试、对比，给出推荐。

**场景 2：验证 skill 质量**
```
测试 [skill名]
```
生成详细评测报告。

**场景 3：横向对比**
```
测试 写文章 相关skill
```
选择多个测试，SUMMARY.md 提供完整对比。

## 注意事项

**不可调用的 skills**
设置了 `user-invocable: false` 的 skill 需手动应用，自动化程度低。

**评分主观性**
基于 AI 判断，建议结合实际使用体验和产出物质量。

**测试覆盖**
每个 skill 仅测试一个典型场景。

## 常见问题

**Q: 可以重新测试吗？**
可以，会覆盖之前的产出物。

**Q: 如何自定义测试场景？**
手动编辑 `[业务类型]/[skill名]/input.md` 后重新测试。

**Q: 如何调整评分标准？**
修改 SKILL.md 中的评分维度说明。
